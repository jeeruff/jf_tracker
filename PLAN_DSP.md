# План: парсер параметров DSP и их отображение (22 окт 2026)

Отдельный план по одной задаче: любой эффект в DSP-панели должен показываться понятно и плотно сам, без ручной раскладки. Кураторские модули (`jf_tracker_dspmods.lua`) остаются для тех плагинов, где ручная раскладка лучше.

## Что видно сейчас (снимок Surge XT, 22 окт)

- Имена режутся по ширине: `highpas`, `feedbac`, `pre gai`, `f2 offs`. Нужно не резать по буквам, а сокращать по словарю (highpass → hp, feedback → fb, pre gain → pre).
- В ADSR-графике (FILTER EG) столбец подписей A / D / S / R обрезан до одной цифры («A 7», «D 1»). Ширина подписи — от длины значения, а не от фиксированного «S +00.00».
- Ромб у `keytrk`, `drive`, `pre gain`: проверить, правда ли у них ноль посередине. Возможно ложное срабатывание симметричного диапазона (±100 %), когда «ноль» — не середина по смыслу.
- `cutoff 25087`: частота показана сырым числом, без «Hz / kHz». Нужен вид значения по единицам (25.1k).
- Параметры-ступени с длинными подписями (`FX Co…`) — полоса, а не список; проверить порог.

## Этапы

### Первое: макро-параметры (22 окт, сделано)
- Модель находит макросы у любого плагина: `Macro 1..8`, `M1..M8`, `M1: имя` (Surge XT), `MC 1` — `M.is_macro_name`, `M.macroize` (у кураторских модулей — поиск в первых 64 параметрах). От 2 до 8 — банк.
- В модуле слева — 8 вертикальных фейдеров (номер под фейдером, имя и значение — в статусе), в раскладке параметров макросы строк не занимают.
- SLIDER (Ctrl+Cmd) над модулем с макросами — сначала его фейдеры макросов.
- Тест: `tests/test_macros.lua`.


### Мини-панель mod · auto в блоке трека (22 окт, сделана основа)
- В блоке трека DSP (широкий вид) — раздел `mod · auto N`: заголовок сворачивает; строки — автоматизированные (`E`) и модулированные параметры трека (`L` LFO, `A` ACS, `K` link); щелчок — к параметру в DSP, ПКМ — его меню модуляции.
- Для выбранного в DSP параметра — кнопки: `lfo`, `acs` (вкл / выкл), `link` (меню: связать с параметром), `env` (огибающая), `side` — зависимость от другого канала: посыл трека-источника в каналы 3/4 и ACS по ним (нативный сайдчейн).
- 22 окт (2): панель — по вертикальной кнопке у правого края блока (блок вдвое шире), XY-пэд снова под строками. LFO — волной, автоматизация — кривой огибающей по песне.
- 22 окт (2): **premod** — кривая до каждой ноты трека (как клипы автоматизации FL): pooled automation items на огибающей, кончаются на нотах, сверка в `edit.run` после каждой правки (`edit.pk_sync`); pre, keytrack, velocity, humanize (детерминированный). Чистая часть — `jf_tracker_premod.lua`, тест `tests/test_premod.lua`. Дальше: premod для параметров внутри контейнеров (ключ по GUID ребёнка), форма из пресетов Anticipate (`Scripts/jf_anticipate_presets`), подкат только по нотам одной высоты / канала.
- 22 окт (3): две вертикальные кнопки auto / mod; панель — сверху автоматизация, снизу модуляция: вкладки lfo / acs / link / env / premod с редакторами (форма LFO, sync, ползунки named config `param.N.*` протяжкой без undo — запись на отпускании, вход 3/4 и side, источник link, кривая огибающей), редактор кривой premod (ромбы), вертикальная пианинка со входом MIDI и метр velocity, test — проба кривой на параметре. Тест `tests/test_modpanel.lua`.
- 22 окт (4): premod на параметрах внутри контейнеров (пэды drumrs5k) и только по одной высоте ноты; вкладка env — кнопка follow (огибающая параметра колонкой, генератор automation в режиме follow).
- Дальше: параметры, модулированные вне показанного списка (сейчас список — из показанных в модуле); follow-огибающая другого трека (генератор LFO-вкладки automation, тип follow) прямо отсюда; глубина / скорость LFO строкой под параметром; гарпун на строку панели.

### 0. Набор образцов (основа для тестов) — сделано 22 окт: `:fxdump`, `jf_tracker_fxdump.lua`, образцы RS5K / Surge XT VST3 / CLAP в `tests/fixtures/fxdump` (Filther, Twin 3 — снять, когда снова в проекте)

### 1. Парсер: модель параметра — сделано 22 окт (основа): `jf_tracker_fxparse.lua` — единица, вид, ноль посередине по 0.5, лог-шкала, словарь сокращений; тест `tests/test_fxparse.lua`. Осталось: огибающие по любой четвёрке a d s r, нумерованные подсекции
- У каждого параметра — `kind`: toggle / steps / note / bipolar / db / freq / time / percent / plain, и `unit` по тексту значения.
- Диапазон и середина — по образцам 0 / 0.5 / 1: ноль посередине — только если в 0.5 значение ≈ 0 (точнее, чем по краям).
- Имя: группа + основа (`FC.split`), короткая подпись по словарю сокращений; полное — в статусе и подсказке.
- Огибающие: любая четвёрка a / d / s / r одной группы (`Amp Attack`, `Env 2 Decay`, `1 A … 1 R`, `f att / f dec`) → группа `env`. Несколько огибающих — несколько графиков.
- Секции: ловить нумерованные блоки (`Osc 1 / Osc 2`, `LFO 1..4`) как подсекции.
- Тест: на образцах — ожидаемые kind, секции, огибающие.

### 2. Виджеты по типу — начато 22 окт: значение не влезает — короткий вид (25.1k, 354ms, -inf, +3.5st), имя — сокращение по словарю. Осталось: шкала частоты / dB у полосы, связанные пары
- db — полоса от −inf, отметка 0 dB; freq — логарифмическая шкала, значение «1.2k»; time — «ms / s»; percent — полоса; bipolar — ромб; note — клавиатура; steps — по числу положений (уже есть); toggle.
- Связанные пары: cutoff + reso → маленькая кривая фильтра; LFO rate + shape → значок формы.
- Значение — по единицам, не сырым числом.
- Тест: функция «текст значения → вид и число» на образцах.

### 3. Раскладка
- Ширина колонки — от длины подписей и значений модуля, не одна на все.
- Столбец значения — по самому длинному значению этого параметра (как у слайдеров шапки).
- Ни одной надписи поверх другой: проверка расчётом на 3 размерах шрифта.
- Секции и вкладки: `zP` и опция `dsptabs` — уже есть; проверить на всех образцах.
- Тест: `D.param_flow` на образцах — без пустых колонок, без обрезанных подписей.

### 4. Кураторское против авто
- Порядок: модуль пользователя (learn) → реестр `dspmods` → авто.
- `:dspsave` — сохранить авто-раскладку плагина как запись реестра (начало для ручной правки).
- Секция / вкладка, переименованная пользователем, сохраняется (файл пользователя, без миграций).

### 5. Взаимодействие
- Режим «all» у кита и любые массовые записи: значение — только явным действием (протяжка, выбор в выпадашке), не одиночным щелчком.
- `i`, Ctrl+Enter, SLIDER (Ctrl+Cmd), XY-пресеты — сверить, что работают на всех видах виджетов.

### 6. Скорость
- Всё, что зависит от типа плагина, — один раз (кэш по имени и числу параметров): kind, секции, сокращения, ноль посередине.
- В кадре — только чтение значений видимых параметров. Бюджет: DSP-панель ≤ 2 ms на кадр (`:jftop`).

## Контейнер и полосы — по максимуму, но наглядно и нативно (23 окт, большой пункт)

Всё — родными средствами REAPER 7 (контейнеры, parallel, pin mapping, JSFX 3/4/5-band splitter / joiner), трекер — только вид и правка; проект играет без трекера.

### Сплиттер полос (3 / 4 / 5 band splitter + joiner)
- 23 окт, сделано (основа): роутер рисует связку полосами (подписи low / mid / high с частотами раздела), эффект — в полосе по входному пину; `a` на полосе — эффект в неё (пины на её каналы, I_NCHAN ≥ 2N), `zb` — эффект в 3 / 4 / 5 полос. Тест — test_dspbig. Дальше: ручки частот на шине, solo / mute полосы, `+` внутри полосы мышью, FFT Splitter.
- Роутер узнаёт связку `[N-band splitter] … [band joiner]` и рисует её как N рядов-полос (low / mid / high …) с частотами разделов на шине; эффекты между ними — в своей полосе по их pin mapping (каналы 1/2, 3/4, 5/6 …).
- Вставка в полосу: `a` / щелчок по `+` полосы — эффект ставится между сплиттером и джойнером, его входы и выходы — на каналы этой полосы (SetPinMappings), число каналов трека — сколько нужно (I_NCHAN).
- Частоты разделов — ручками прямо на шине (параметры сплиттера), solo / mute полосы (pin bypass), громкость полосы.
- Команда «split into 3 / 4 / 5 bands»: на выбранный эффект / ряд — сплиттер + джойнер вокруг.

### Зоны цепей Key / Vel / Chain (Instrument Rack Ableton) — 23 окт, сделано (основа)
- `Effects/jf_tracker_zone.jsfx` — первым в цепи: зоны key / vel / sel (lo..hi звучит, flo..fhi в полную силу, скаты линейно); нота вне зоны глушится вместе с note-off, в скате velocity × скат; аудио × скат sel (цепи эффектов). Слайдер select (13) — общий регулятор, трекер пишет его во все цепи.
- `jf_tracker_zones.lua` (Z.gain / Z.drag / Z.label) — тот же расчёт, тест `tests/test_zones.lua`.
- Вид: список цепей контейнера (zv) — кнопки key / vel / chain; справа полосы зон по линейке (октавы C / 0 32 64 96), края, скаты (верхняя половина) и вся зона тянутся мышью; плагин зоны ставится в цепь при первой правке (одиночный эффект заворачивается в цепь). chain — янтарный бегунок select в линейке.
- Дальше: select как параметр контейнера (learn / автоматизация одним регулятором — сейчас пишется во все цепи), то же в цепях пэда drumrs5k, громкость / пан цепи (dB) в строке.

### Chain selector (как Chain Select в Ableton Rack) — план, 23 окт
- 24 окт, сделано (основа): ПКМ на контейнере — Chain select on a macro → M1..M8: в каждой цепи зона, её select выведен параметром цепи (container_map), а он ссылкой (plink) на ручку макроса контейнера. Проверено живьём: M1 = 0.5 → select 64. Зоны sel у цепей — zv chain.
- Цель: один регулятор 0..127 (ручка / CC / нота / velocity) выбирает, какие параллельные цепи контейнера звучат; у цепи — зона [lo..hi] и плавные края (fade), цепи перекрываются — кроссфейд.
- Нативно: внутри контейнера первым — свой маленький JSFX `jf_chain_select` (без звука: 8 выходных слайдеров = громкость цепи 1..8 по зонам, вход — слайдер select и зоны lo / hi / fade каждой цепи); wet (или громкость) каждой цепи — parameter link REAPER на свой слайдер (`param.N.plink`, scale 1). Регулятор select — обычный параметр: учится на MIDI (REAPER learn), автоматизируется, макрос контейнера.
- Источник по выбору: CC (learn), нота (высота → select, как keyzone), velocity (vel zone), LFO / огибающая (модуляция REAPER на select).
- Вид в трекере: в списке цепей (zv) — полоса 0..127 у каждой цепи с зоной и скатами (тянуть края мышью, как в Ableton), бегунок текущего select; в DSP / роутере — громкость цепи живьём.
- Проверить до кода: plink между детьми одного контейнера (адреса 0x2000000+…), что wet контейнера-ребёнка автоматизируется; тест — расчёт громкостей по зонам (чистая функция).

### Что уже есть в REAPER для роутера (23 окт, разведка установленных JSFX и API)
- **Полосы:** `loser/3BandSplitter`, `4BandSplitter`, `5BandSplitter` + `…Joiner` — кроссовер в пары каналов (1/2, 3/4, 5/6…), частоты — слайдеры; `schwa/fft_splitter` — фазово-линейный FFT-сплиттер (без сдвига фаз полос).
- **Каналы и смесь:** `utility/channel_mapper` (Channel Mapper-Downmixer), `utility/channelmixer`, `IX/PhaseAdjustingRouter` (роутер каналов с полярностью), `IX/Mixer_8xS-1xS` / `8xM-1xS` (сумма 8 пар в одну — свой джойнер на 8 веток), `IX/Switcher2` (выбор 1 из 8 входов — A/B веток, «переключатель» как кнопка), `IX/StereoPhaseInvert`.
- **Мид / сайд, ширина:** `sstillwell/stereowidth`, `sstillwell/width`, `Liteon/rbjstereofilter12db`, `loser/stereoEnhancer` — ветки M/S.
- **API:** контейнеры (`container_count`, `container_item.N`, `parallel` 0/1/2 — 2 = parallel с MIDI-merge), `container_nch` / `container_nch_in` / `container_nch_out` (каналы контейнера), `TrackFX_Get/SetPinMappings` (какие каналы видит эффект), `I_NCHAN` трека, parameter link между детьми контейнера (`param.N.plink`, у контейнера — свои параметры-макросы через «container parameter»), `TrackFX_CopyToTrack` с адресами контейнера, `.RfxChain` — пресет цепочки.
- **Как использовать:** полоса = пара каналов: эффект в полосе — pin mapping на эту пару; сумма — Joiner или Mixer_8x; A/B — Switcher2; M/S — ветка с stereowidth / channel mapper. Свой JSFX не нужен — всё штатное.

## Ручки: кноб и двойной пуш-пул кноб (24 окт, план)

Третий элемент рядом с полосой и ромбом. Вдохновение — пульты Nagra IV-S, Kudelski, швейцарские усилители, советские «Поливокс» / «Электроника»: шкала и подписи вокруг ручки, указатель — риска / планка, по значению видно, где стоит, а не только «сколько».

- Кноб (основа сделана 24 окт: `D.knob` — дуга 270°, тусклая — ход, яркая — значение, риска; ручки громкости цепей в шапке контейнера, тянуть вверх / вниз, Shift — мелко). Дальше: шкала рисками вокруг (по шагам параметра: 2–8 позиций — риски с подписями, как переключатель «мин 1 2 3 4 5 макс»), ноль посередине у биполярных (дуга от верха в обе стороны), подпись снизу, значение — по наведению.
- Двойной пуш-пул кноб: два концентрических кольца — внешнее и внутреннее (как Nagra LEVEL: внешний диск + красная внутренняя ручка). Одна ручка — два параметра (например, cutoff снаружи и reso внутри; Wet и Gain цепи). Тянуть по внешнему кольцу — первый, по центру — второй; Option — второй с любого места. Клавиши: h l / j k — первый, Shift — второй (по философии модификаторов уточнить).
- Переключатель-ручка (rotary switch): ступени 3–8 — планка-указатель на подписях вокруг (как «РЕЖИМ ГЕНЕРАТОРА ОГИБАЮЩЕЙ» / Kudelski TEST-RECORD), щелчок по подписи — сразу туда. Правило «кнопка — 2 положения» не нарушает: это не кнопка-перебор, а шкала.
- Где: опция вида параметров модуля (полосы | ручки), автомодуль — ручки для «главных 8» в строке над колонками; кураторские модули — явно (`knob = true`, `pair = { a, b }`).
- Размер — от строки (r ≈ высота строки) и «крупно» (2×2 строки) для главных; текст никогда не накладывается (правило), подписи шкалы — только если влезают.
- Тест: раскладка ручек и попадание мыши (внешнее / внутреннее кольцо) без REAPER.
