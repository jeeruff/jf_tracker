# План: парсер параметров DSP и их отображение (22 окт 2026)

Отдельный план по одной задаче: любой эффект в DSP-панели должен показываться понятно и плотно сам, без ручной раскладки. Кураторские модули (`jf_tracker_dspmods.lua`) остаются для тех плагинов, где ручная раскладка лучше.

## Что уже есть

| Слой | Где | Что делает |

| Реестр кураторских модулей | `jf_tracker_dspmods.lua` (`DM.modules`) | Surge XT, RS5K, slixer, ReaEQ и др.: параметры по подстроке имени, группы, страницы (`pages`), `heads` |
| Классификатор | `jf_tracker_fxclass.lua` (`FC`) | `FC.junk`, `FC.split` (группа + имя), `FC.class` (категория по единицам и словам), `FC.rank`, `FC.auto` (42 главных), `FC.section` / `FC.pages` (секции синта: osc filter env lfo mod fx) |
| Модель | `jf_tracker_model.lua` | `param_entry` (toggle / steps / slider по шагам), `M.auto_module` (кэш на тип плагина), страницы / `heads` для автомодуля, `M.bipolar_of` / `M.param_bipolar` (ноль посередине, кэш) |
| Раскладка | `jf_tracker_draw.lua` | `D.param_rows`, `D.param_flow` (колонки с высотой и секциями), `ncol_of`, вкладки страниц (опция `dsptabs`) |

## Что видно сейчас (снимок Surge XT, 22 окт)

- Имена режутся по ширине: `highpas`, `feedbac`, `pre gai`, `f2 offs`. Нужно не резать по буквам, а сокращать по словарю (highpass → hp, feedback → fb, pre gain → pre).
- В ADSR-графике (FILTER EG) столбец подписей A / D / S / R обрезан до одной цифры («A 7», «D 1»). Ширина подписи — от длины значения, а не от фиксированного «S +00.00».
- Ромб у `keytrk`, `drive`, `pre gain`: проверить, правда ли у них ноль посередине. Возможно ложное срабатывание симметричного диапазона (±100 %), когда «ноль» — не середина по смыслу.
- `cutoff 25087`: частота показана сырым числом, без «Hz / kHz». Нужен вид значения по единицам (25.1k).
- Параметры-ступени с длинными подписями (`FX Co…`) — полоса, а не список; проверить порог.

## Этапы

### 0. Набор образцов (основа для тестов)
- Команда `:fxdump` (только по команде): для FX под курсором — имена параметров и текст значения при 0 / 0.25 / 0.5 / 0.75 / 1 (через `FormatParamValueNormalized`, без записи в плагин), число шагов, toggle — в `Data/fxdump/<плагин>.txt`.
- Снять 10–15 плагинов: Surge XT, Twin 3, Vital, Diva, 2op PM, Filther, ReaEQ, ReaComp, RS5K, Airwindows, Saike, TAL, Abyss.
- Образцы — в `tests/fixtures/`, парсер проверяется на них без REAPER.

### 1. Парсер: модель параметра
- У каждого параметра — `kind`: toggle / steps / note / bipolar / db / freq / time / percent / plain, и `unit` по тексту значения.
- Диапазон и середина — по образцам 0 / 0.5 / 1: ноль посередине — только если в 0.5 значение ≈ 0 (точнее, чем по краям).
- Имя: группа + основа (`FC.split`), короткая подпись по словарю сокращений; полное — в статусе и подсказке.
- Огибающие: любая четвёрка a / d / s / r одной группы (`Amp Attack`, `Env 2 Decay`, `1 A … 1 R`, `f att / f dec`) → группа `env`. Несколько огибающих — несколько графиков.
- Секции: ловить нумерованные блоки (`Osc 1 / Osc 2`, `LFO 1..4`) как подсекции.
- Тест: на образцах — ожидаемые kind, секции, огибающие.

### 2. Виджеты по типу
- db — полоса от −inf, отметка 0 dB; freq — логарифмическая шкала, значение «1.2k»; time — «ms / s»; percent — полоса; bipolar — ромб; note — клавиатура; steps — по числу положений (уже есть); toggle.
- Связанные пары: cutoff + reso → маленькая кривая фильтра; LFO rate + shape → значок формы.
- Значение — по единицам, не сырым числом.
- Тест: функция «текст значения → вид и число» на образцах.

### 3. Раскладка
- Ширина колонки — от длины подписей и значений модуля, не одна на все.
- Столбец значения — по самому длинному значению этого параметра (как у слайдеров шапки).
- Ни одной надписи поверх другой: проверка расчётом на 3 размерах шрифта.
- Секции и вкладки: `zP` и опция `dsptabs` — уже есть; проверить на всех образцах.
- Тест: `D.param_flow` на образцах — без пустых колонок, без обрезанных подписей.

### 4. Кураторское против авто
- Порядок: модуль пользователя (learn) → реестр `dspmods` → авто.
- `:dspsave` — сохранить авто-раскладку плагина как запись реестра (начало для ручной правки).
- Секция / вкладка, переименованная пользователем, сохраняется (файл пользователя, без миграций).

### 5. Взаимодействие
- Режим «all» у кита и любые массовые записи: значение — только явным действием (протяжка, выбор в выпадашке), не одиночным щелчком.
- `i`, Ctrl+Enter, SLIDER (Ctrl+Cmd), XY-пресеты — сверить, что работают на всех видах виджетов.

### 6. Скорость
- Всё, что зависит от типа плагина, — один раз (кэш по имени и числу параметров): kind, секции, сокращения, ноль посередине.
- В кадре — только чтение значений видимых параметров. Бюджет: DSP-панель ≤ 2 ms на кадр (`:jftop`).

## Открытые вопросы
- Словарь сокращений — общий файл пользователя или в коде?
- Нужна ли кривая фильтра, или достаточно правильной шкалы частоты?
- `:fxdump` — писать в `Data/` проекта или в `Scripts/jf_tracker/tests/fixtures/` (для разработки)?
- Огибающие из одной буквы (`1 A`): ловить только при полной четвёрке A D S R подряд?
