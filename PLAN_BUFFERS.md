# Любая панель — буфер (план, 12 ноя)

Сейчас: дерево сплитов (jf_tracker_panes.lua) держит панели по id; модуль = один экземпляр, его курсор /
прокрутка / выбор — поля таблицы модуля (IN.r, RF.sel, MM.scroll …), у каждого своё имя и свой код прокрутки.
Цель: панель показывает **буфер** = { модуль, состояние }. Два трекера на разных паттернах, два DSP разных треков,
lib в две колонки. Одна прокрутка / курсор / фокус на всех — модулю не нужно своё.

## Как без опасности (по шагу, всё зелёное после каждого)
1. **Буфер-обёртка без изменения поведения.** `jf_tracker_buffers.lua`: `B.new(mod, opts)` → { id, mod, st };
   `st` — общие поля (cur, scroll, sel, focus). Для каждого модуля буфер №1 — **алиас** нынешней таблицы:
   `st` указывает на сам модуль (IN, RF…). Ничего не переписано — работает как сейчас. Тест: все tests зелёные.
2. **Общая прокрутка / курсор.** `B.scroll(b, d)`, `B.cur(b, d)`, колесо и j/k у панели — в одном месте вместо
   ctx.vbar_scroll с ветками по ключам. Модули переводятся по одному (с тестом на модуль): поле `IN.r` → `st.r`.
3. **Второй экземпляр.** Панели в дереве — `id#n` (`dsp#2`). Модуль, переведённый на `st`, получает второй буфер;
   не переведённый — нет (кнопка не предлагает). Первые: dsp (свой трек — «закреплён» или «за курсором»), tracker
   (свой паттерн / треки), lib (вторая колонка — папка).
4. **API**: `ctx.buf()` — буфер в фокусе; команды (:, which-key, экшены MIDI) работают с ним, а не с модулем.

## Риск и защита
- Главный риск — роутер клавиш / фокуса в jf_tracker.lua (guard-списки по id). Защита: id панели остаётся
  именем модуля (`dsp#2` → модуль `dsp`), guard-списки сравнивают имя модуля; тест на роутер с двумя буферами.
- Тесты-снимки до шага 1: обход фокуса, прокрутка каждого модуля — сравнение до / после.
- Трекер №2 — последним: снимок model один, второй вид = другой паттерн / диапазон, не вторая модель.
